# REQ-0016：链接的悬停操作与行内源码编辑

**类型**：feature

## 1. 场景叙述

用户在所见即所得编辑器中看到超级链接时，鼠标悬停在链接上会弹出「编辑 / 访问链接」两个选项；
点「访问链接」在系统默认浏览器打开网页链接（Markdown/代码文件仍在应用内打开），点「编辑」进入源码编辑。
直接单击链接也进入源码编辑：该链接在正文中原地展开为 Markdown 源码 `[文字](地址)`，可以直接修改；
按 Enter 或点击别处提交，按 Esc 取消。

结果是：改链接不必切到全文源码模式，访问网页也不必先复制地址；编辑与阅读在同一视图里完成。

## 2. 价值

不做的后果：用户改一个链接地址要按 ⌘/ 进整篇源码模式定位，或只能通过 ⌘K 重设整段；
访问链接只能靠默认单击导航，和「单击即编辑」的所见即所得习惯冲突。

## 3. 非目标

- 不做浏览器内嵌预览、链接预览卡片、链接检查器或 favicon。
- 不改全文源码模式（⌘/）与 Markdown 序列化规则。
- 不引入新的链接语法；引用式链接、HTML 标签链接的编辑按解析后的 Markdown 源码展开。
- 不做链接的拖拽排序、批量修改或自动补全。

## 4. 行为约定

- 链接在渲染态仍显示为链接文字；单击不导航。
- 悬停弹层：两个动作「编辑」「访问链接」；鼠标移出后收起。
- 单击链接 → 原地展开该链接的 Markdown 源码；只展开被点的链接，其余正文保持渲染态。
- 源码编辑：Enter 或失焦提交，Esc 取消；空源码提交等于删除该链接。
- Command+单击：直接访问链接，不进入编辑。
- 访问策略：`http`/`https`/`mailto`/`tel` 交给系统默认应用（网页即默认浏览器）；
  `file://` 或相对路径的 Markdown/代码文件在应用内新窗口打开，其他本地文件交给系统默认应用；
  纯 `#anchor` 在文档内滚动到对应标题。
- 访问行为由壳执行（系统默认应用/窗口路由），内核只上报意图；不把宿主 API 下沉进 web 内核。
