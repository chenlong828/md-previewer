# REQ-0015：Dock 右键菜单切换已打开窗口

**类型**：feature

## 1. 场景叙述

用户同时开了多个文档窗口，在 Dock 上右键应用图标，菜单顶部直接列出当前所有已打开窗口
（文件名，当前窗口带勾选）；点其中一项，对应窗口立即前置并成为当前窗口，最小化的窗口
同时恢复。用户不必先用 ⌘` 或「显示所有窗口」/Mission Control 找窗口，再从一堆窗口里挑。

结果：多窗口时按名字直接切到目标文档，窗口管理成本与窗口数量基本无关。

## 2. 价值

不做的后果：Dock 菜单只有「选项 / 显示所有窗口 / 隐藏 / 退出」等通用项；多窗口下要切到
某个文档，只能反复 ⌘` 轮换、打开「显示所有窗口」网格逐一看标题，或在 Dock 图标上点一下
再用 Mission Control 找。省下的路径切换可直接换算成阅读/写作时间的损失。

## 3. 非目标

- 不做标签页、窗口合并、窗口分组或会话恢复。
- 不在菜单里提供关闭、最小化其他窗口等管理动作（保持精简；「显示所有窗口 / 隐藏 / 退出」
  仍由 macOS 附加的标准项提供）。
- 不把「最近打开」放进 Dock 菜单；最近文件仍在「文件 → 打开最近使用」。
- 不做窗口重命名、置顶、图标或分组标记。
- 不改变窗口打开/关闭语义（外部打开新窗口、⌘O 替换、关闭即销毁窗口）。

## 4. 行为约定

- 仅当应用运行中且至少有一个文档窗口时，Dock 菜单出现自定义条目；条目按窗口创建顺序排列。
- 条目标题 = 窗口标题（文件名 / 目录名 / 「未命名」），与窗口标题栏一致；同名窗口并列显示，
  悬停提示给出完整路径。
- 当前窗口（key/main；应用未激活时为最前置的文档窗口）条目带勾选状态；菜单每次打开时按当时窗口状态重建。
- 点击条目：激活应用、目标窗口置前并成为 key window；已最小化的窗口先恢复。
- 窗口关闭后条目立即消失；条目只引用现存窗口，不缓存已关闭窗口。
- 自定义条目位于菜单顶部，其下由 macOS 附加标准项（选项、显示所有窗口、隐藏、退出）。

## 5. 影响场景

| 场景 | 状态 | 本次新增/修改的断言 |
|---|---|---|
| [SCN-0021 从 Dock 菜单切换窗口（新建）](../design/scenarios/navigation/windows/dock-window-switch/scenario.md) | designed | 条目与窗口一一对应、当前窗口勾选、点击切换（含最小化恢复）、关闭后条目消失 |

SCN-0013（多窗口与外部打开）的窗口模型断言不变，本需求只新增切换入口。

## 6. 验收

验收 = SCN-0021 `verified` + §4 约束未被违反。

自动化：`--dockmenu-test`（3 正 1 反，见场景卡 §5；自备临时文档）。人工：真实右键 Dock 图标，
确认条目顺序、勾选与点击切换手感（构建后确认）。

## 7. 澄清记录

- 2026-11-20 用户要求：类似 PowerPoint 的 Dock 右键菜单，直接列出已打开实例，方便快速切换与管理。
- 2026-11-20 三选一确认：菜单内容 = 只列当前打开的窗口；显示 = 文件名 + 勾选当前窗口；
  管理动作 = 不加关闭/批量动作，保持精简。

展开与勾选视觉待用户点验，故暂不转 `delivered`。
