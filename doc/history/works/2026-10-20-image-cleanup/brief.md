# 工序: 图片资源生命周期管理(撤销残留与关闭清理)

## 需求

1. **撤销残留**: 粘贴截图/拖入图片会立即落盘 `resource/<md文件名>/`,用户
   发现不合适按 ⌘Z 撤销后,节点从文档消失,但磁盘文件残留。
2. **关闭清理**: 文档编辑中删除图片引用(或重写正文不再引用),对应磁盘文件
   成为死链残留;文档关闭时应清理死链图片等附件。

两者同属一个事实:资源目录里存在**未被当前文档引用**的文件。用同一机制解决。

## 已核实的现状

- 关闭链路: `windowShouldClose`(脏→sheet 确认)→ `beginConfirmClose`
  (保存/不保存/取消)→ `performClose`;`completion(true)` 仅在磁盘内容已是
  权威终态时回调。**无 windowWillClose 钩子**;`window.delegate = self`
  显式设置(DocumentWindowController.swift:53),delegate 方法可直接新增。
- 图片语法解析单源在 `ImagePathRewriter`(Util.swift):宽松两段式正则 +
  `splitInner`(`<>` 包裹/引号标题)+ `mapLinesOutsideFences`(围栏内不算)。
- 保存定式(forSave):目录内相对路径用 `<>` 包裹(含空格/括号时),file://
  以 %20 编码——磁盘上的引用形态即此三种(相对/包裹/编码)+手写绝对 file://。
- `ImageStore.existingFiles` 已是抛错语义(本日 P3 修复),列举失败不再静默。

## 领取的设计决策(2026-10-20 用户定稿)

- **清理时机: 关闭时统一 GC**(用户三选一选定,否决「撤销时立即删」)——
  理由:撤销立即删盘会让 ⌘⇧Z 重做指向已删文件变破图,要保重做需加会话缓存
  层,复杂度与收益不成比例;关闭 GC 单机制覆盖两类残留,撤销孤儿最多存活到
  关闭,崩溃残留在下次关闭该文档时同样被清。
- **清理范围: `resource/<md文件名>/` 目录内 UTType 判定为图片**的文件;
  非图片文件一律不动(未来附件类型扩展时在此放行,也不误删用户手放杂物)。
- **判定权威: 关闭时从磁盘读文档**(保存/放弃决策已定,磁盘=终态;放弃场景
  下本会话粘贴孤儿被正确清除)。

## 验收标准

1. 引用形态全覆盖:相对路径、`<>` 包裹(含空格)、`%20` 编码 file://、
   手写绝对 file:// 均保护文件;围栏内同名写法**不**保护。
2. 孤儿删除、被引用图片与目录内非图片文件(如 notes.txt)保留。
3. 图片全清且无其他文件时,`resource/<md文件名>/` 与 `resource/` 连带移除;
   还有其他文件时目录保留。
4. selftest 新增用例全绿;既有 89 项不回归;eslint 干净。
5. 关闭钩子人工验证:新建文档粘贴图片→撤销→关闭(不保存)→Finder 确认
   resource 目录无残留;再粘贴→保存→关闭→文件仍在。

## 边界(本工序不做)

- 非图片附件(现无附件类型;GC 的类型放行点已预留,扩展另立工序)。
- 打开时 GC(避免误删用户手动放入但尚未引用的文件;崩溃残留靠下次关闭清理)。
- 跨文档共享同一 resource 子目录(不支持,README 已知边界写明)。
- 清理失败的用户可见提示(仅 os_log,不打断关闭;偶发慢路径与导入同纪律)。
